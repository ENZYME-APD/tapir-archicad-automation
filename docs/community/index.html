How to report a bug

Post it in Discord or open an issue on GitHub. Both reach the same place: a bot files bug reports and feature requests from Discord as GitHub issues and replies with the link. A GitHub account is not needed to report on Discord.

A report that can be fixed in one go says:

  • your Archicad version and build, and its language (for example 29.0.0 (3100) INT);
  • your Tapir version (the About Tapir dialog shows it);
  • what you did: the script or Grasshopper definition, or the command and the JSON you sent;
  • what you expected and what happened instead, with the error message;
  • whether the project is a Teamwork project, and which libraries are loaded, when it matters.

⚠ Note Issues and Discord channels are public. Leave out client names, project names and file paths you don't want to share.

From report to release: how the bots work

Most fixes are written by bots and checked by people. The maintainers set the rules and can stop any change; you decide whether a fix works in your Archicad.

  1. The report becomes an issue

    Every half hour the Discord bot reads the project's channels. A message that reads like a bug report or a feature request becomes a GitHub issue, labelled bug or enhancement, and the bot replies in Discord with its link. Chat and questions stay on Discord.

  2. The issue bot answers

    Every new issue is read by the issue bot. It answers a question, closes an issue that is already fixed, asks for what it is missing (your Archicad version, the JSON you sent), or writes the fix and opens a pull request. A large request is split into parts, one pull request each.

  3. It is built and reviewed

    The add-on is built for every supported Archicad version, on Windows and macOS, and a review bot reads the change. When a build fails or the review finds a problem, the bot fixes it. After a few rounds without success it hands the pull request to a maintainer.

  4. You test it

    Once the builds pass, a comment on the pull request links the built add-on and asks the person who reported the issue to try it. How to test a fix is below. A problem you report there is fixed before the pull request is merged.

  5. It is merged and released

    When every build is green and the review finds nothing blocking, the pull request is merged three days later, unless a maintainer stops it. Every Monday the changes since the last release ship as a new release, and the add-on offers to update itself.

How to test a fix

A fix is only known to work once someone has run it in Archicad. The bots can build Tapir but cannot run Archicad, so your test is what matters most.

  1. Open the pull request linked from your issue. A comment on it lists the downloads, one per Archicad version and platform. Downloading needs a GitHub login.
  2. Unzip the download for your Archicad version. On macOS it holds another zip with the .bundle.
  3. In Archicad, open Options > Add-On Manager > Edit List of Available Add-Ons, remove or disable the installed Tapir, then Add the .apx (Windows) or .bundle (macOS) and click OK.
  4. Do what went wrong before, in a copy of your project.
  5. Say on the pull request whether it works and fixes your case. Afterwards, put your installed Tapir back the same way.

Testing often? The community test runner tests open pull requests on your own Archicad while it is closed, leaves your Tapir in place and posts the result on the pull request. It runs on Windows and needs Python and a GitHub account.
