Tapir / Scripts / Share

Share a script from Archicad.

No GitHub account, no setup. Your name stays on it, and everyone who uses Tapir can install it.

What happens

  1. 1Send itPost the script in #share-a-script on Discord, with a few words on what it does. The Tapir palette is getting a Share button that does the same: you see the whole file before anything is sent. It arrives as a GitHub issue labelled script-share.
  2. 2Adapted for any officeTapir's bot, an AI, opens a pull request: hard-coded layers, properties and paths become settings, risky code is removed, and it works in every Archicad language, in metric and imperial.
  3. 3You confirm, it's listedTry the adapted version and say it still does what you meant. Once the pull request is reviewed and merged, it appears on the Scripts page with your name.

The small print
What is sent

Only the script

The file, your one-line description, the name to credit, and your Archicad and Tapir versions. Nothing from the open project.

Licence

Free for everyone

Every shared script is free and open source. Unless you choose another open-source licence, yours is published under the MIT licence: anyone may use, change and share it, as long as they keep your name and the licence with it. It comes without warranty. You stay its author, and its page credits you.

Only share a script you wrote, or one whose author agreed to share it.

What the AI changes

What the AI changes.

It keeps what your script does. It changes how, so the script is safe and works in other offices, and lists every change in plain words in the pull request.

Made safe

Removed, or flagged for a maintainer

  • connections to anything other than Archicad on your own computer;
  • running other programs or code built from text (subprocess, os.system, eval, exec);
  • installing packages while it runs (pip install);
  • deleting or overwriting files, and writing anywhere but the project's folder and Documents/Tapir;
  • passwords, tokens and keys;
  • user names, C:\Users\… paths, and project, client and office names, in the code and its comments.
Made to fit other offices

Settings instead of your names

  • Property names, layers, stories, paths and classification codes you typed in become settings at the top of the script, or fields of its window.
  • Built-in properties are found by their ID, so the script works in every language of Archicad.
  • Lengths and areas work in metric and imperial units; paths work on Windows and macOS.
Made safe to run

No surprises

  • It says what it is about to change, and does nothing, saying so, when nothing fits.
  • It makes its changes in one Undo step where it can.
  • When a property or element type it needs is missing, it shows a clear message instead of crashing.
Described

A README in plain words

  • What it does, how to use it, its settings, what it changes, its limits, and Original by you.
  • Its category, the Archicad and Tapir versions it works with, and whether it changes the model, writes files or only reads.
Review
Before it is merged

What the review checks

Every pull request is reviewed before it is merged, like any other code in Tapir. The review checks that:

  • nothing on the Made safe list is left in, unless a maintainer agreed to it;
  • the script still does what you wrote it for, and you confirmed that;
  • the folder has the files and fields the marketplace format asks for;
  • the README is accurate, and the screenshots show no client, project or people.
