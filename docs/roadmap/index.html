What's next.

Tapir grows from requests. Most new commands, components and fixes start as a message from someone who needed them in their own work.

How to ask for a feature.

Four steps from "I need this" to a Monday release.

  1. 1

    Say what you want to do

    Post it on Discord or open an issue on GitHub. Describe the task in Archicad, not only the command: "number the doors along a line", "read the area of every zone". A Discord message that reads like a feature request becomes a GitHub issue by itself, labelled enhancement.

  2. 2

    Asking for a part of the Archicad API?

    The API coverage page lists every function of the Archicad API and whether Tapir has a command for it. Use the Archicad API request issue form to ask for one that is missing.

  3. 3

    The issue bot picks it up

    A clear, wanted request is built like a fix: the bot writes it and opens a pull request, and you are asked to try it. A large one is split into parts. When the design is open, the bot describes the choices and a maintainer decides.

  4. 4

    It ships on a Monday

    Merged changes are released every Monday. The release notes list them, and the add-on offers to update itself.

Recently shipped

Already here.

Asked for on the old site's "What's cooking" list, and now part of Tapir.

  • Stairs, roofs and curtain walls

    Read and change them: ModifyStairs, ModifyRoofs and ModifyCurtainWalls.

  • Building materials and composites

    Create them from a script: CreateBuildingMaterials and CreateComposites.

  • Dialogs from Python

    A script shows its own window in Archicad: ShowScriptUI and GetScriptUIResult.

  • 2D detailing

    Lines, fills and text: CreateLineElements, CreateHatches and CreateTexts.

  • Your own properties

    Add property definitions from a script: CreatePropertyDefinitions.

  • Built-in scripts

    Ready to run from the palette, from numbering to a project health check. See them on GitHub.
